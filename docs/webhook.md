# Получение брифов из Cyber Brief

Cyber Brief записывает встречи в Яндекс Телемосте, расшифровывает их и
собирает бриф: решения, задачи, идеи, открытые вопросы. Готовый бриф он
может отдавать не только в Телеграм, но и вашему сервису.

Ставить ничего не нужно: вы поднимаете один обработчик HTTP, мы шлём
в него POST.

## Как это работает

```
встреча закончилась -> расшифровка -> бриф -> POST на ваш адрес
```

Доставка начинается сразу после того, как бриф ушёл людям в Телеграм.
Если ваш сервис недоступен, мы повторяем три раза с нарастающей паузой
и дальше сдаёмся: бриф не пропадёт, он остаётся в истории бота.

## Что приходит

`POST` с телом JSON в кодировке UTF-8 и заголовками:

| Заголовок | Значение |
|---|---|
| `X-Cyber Brief-Event` | `brief.ready` |
| `X-Cyber Brief-Meeting` | идентификатор встречи |
| `X-Cyber Brief-Signature` | `sha256=<подпись тела>` |

Тело:

```json
{
  "meeting_id": "20261002-101406-f556",
  "title": "Встреча в Телемосте, 02.10 10:14",
  "started": "02.10 10:14",
  "started_ts": 1791000846.5,
  "duration_sec": 2520,
  "url": "https://telemost.yandex.ru/j/…",
  "requester": "Александр",
  "speakers": ["Иван Петров", "Мария Соколова", "A", "B"],
  "brief": { "…": "структура, см. ниже" },
  "brief_text": "готовый текст с разметкой Telegram HTML",
  "transcript": "[00:00:12] Иван Петров: …"
}
```

`speakers` — кто говорил. Имена подставлены там, где человек узнан
по голосу; остальные остаются буквами.

`brief_text` — то же, что видят люди в Телеграме. Годится, чтобы
переслать как есть.

`transcript` — полная стенограмма с метками времени и говорящими.
На двухчасовой встрече это сотни килобайт, учитывайте при хранении.

### Структура `brief`

| Поле | Что внутри |
|---|---|
| `headline` | одна фраза: зачем собирались и чем кончилось |
| `tldr` | короткий пересказ списком |
| `decisions` | `{text, quote}` — что решили и дословная цитата |
| `tasks` | `{what, owner, due, quote}` — поручения |
| `ideas`, `insights` | предложения и наблюдения |
| `open_questions` | что осталось нерешённым |
| `next_steps` | следующие шаги |
| `blockers` | `{who, problem, fix, ts}` — у кого что не получилось |
| `speakers` | `{label, name, evidence}` — кого как опознали |
| `numbers` | значимые числа из обсуждения |

Поля с пустыми списками приходят пустыми, а не отсутствуют. Отдельных
полей может не быть вовсе — проверяйте наличие, не полагайтесь на схему
жёстко: она дополняется.

## Проверка подписи — обязательна

Адрес вашего обработчика рано или поздно становится известен. Подпись —
единственное, что отличает наш запрос от чужого.

```python
import hashlib, hmac

def check(body: bytes, header: str, secret: str) -> bool:
    mine = "sha256=" + hmac.new(secret.encode(), body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(header, mine)
```

Считайте подпись от **сырого тела запроса**, до разбора JSON: любая
перекодировка изменит байты и сломает сверку. Сравнивайте через
`compare_digest`, а не `==`.

Секрет вам выдаст владелец Cyber Brief. По сети он не передаётся.

## Минимальный обработчик

```python
from fastapi import FastAPI, Header, HTTPException, Request

app = FastAPI()
SECRET = "…"

@app.post("/hooks/ai-brief")
async def brief_ready(request: Request,
                      x_ai_brief_signature: str = Header(default="")):
    body = await request.body()
    if not check(body, x_ai_brief_signature, SECRET):
        raise HTTPException(401, "подпись не сходится")
    data = await request.json()
    # ваша логика: положить в базу, разослать, поставить задачи
    return {"ok": True}
```

Отвечайте быстро: мы ждём ответа 30 секунд. Долгую обработку делайте
после ответа, а не до него.

## Что учесть

**Повторы возможны.** При сетевом сбое один и тот же бриф может прийти
дважды. Считайте `meeting_id` ключом и обрабатывайте повтор как замену,
а не как новую встречу.

**Встреча может прийти частями.** Если бот заходил на одну встречу
несколько раз (обрыв связи, перезапуск), придёт несколько событий
с разными `meeting_id`. В Телеграме такие части склеиваются в истории,
в webhook — нет.

**Личные данные.** В стенограмме звучат имена, цифры и внутренние
обсуждения. Храните её там же, где храните остальную рабочую переписку,
и не пересылайте наружу без решения владельца.

## Подключение

Отдайте владельцу Cyber Brief две вещи: адрес обработчика и секрет для
подписи. Он добавит их в настройки, и следующая же встреча придёт вам.
