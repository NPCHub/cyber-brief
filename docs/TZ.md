# Cyber Brief: как это устроено и почему именно так

Документ объясняет задачу, варианты решения и причины выбора. Как поставить
и пользоваться — в [README](../README.md).

## 1. Задача

После рабочей видеовстречи в Яндекс Телемосте итоги теряются: кто-то ведёт
заметки, кто-то нет, задачи не доезжают до трекера. Нужен сервис, который сам:

1. попадает на встречу,
2. пишет звук,
3. расшифровывает его с разделением по спикерам,
4. собирает структурированный бриф: решения, задачи, идеи, открытые вопросы,
5. присылает бриф в Telegram сразу после встречи.

## 2. Что умеет Телемост

### 2.1 API записи не даёт

У Телемоста есть официальный API (`cloud-api.yandex.net/v1/telemost-api`), но
в нём только создание и чтение встреч, управление со-организаторами и
настройки организации. **Эндпоинтов на запись, расшифровку, список участников
и подключение ботов нет.** Подключиться к встрече через API нельзя; звук
приходится добывать обходным путём. API к тому же доступен только аккаунтам
Яндекс 360 для бизнеса.

### 2.2 Запись средствами самого Телемоста

- В облако (Яндекс Диск) — только на доменном аккаунте организатора и платном
  тарифе; файл падает в папку «Записи Телемоста», обработка до 24 часов.
- Локально — любой участник, файл `.webm` у него на компьютере.
- SIP-подключение — платный аддон «SIP-коннекторы».

### 2.3 Встроенный AI Яндекса

В Яндекс 360 для бизнеса есть транскрипция и конспект, результат уходит
на почту. Он общий, не настраивается под нужные рубрики (задачи с исполнителем
и сроком, идеи, открытые вопросы) и не попадает в Telegram.

## 3. Четыре пути добыть звук

| | A. Запись с Диска | B. Бот-участник (браузер) | C. SIP-участник | D. Live-stream |
|---|---|---|---|---|
| Как | опрос Диска, скачивание `*_audio_only.webm` | Chromium в Docker заходит по ссылке, звук снимается с виртуальной звуковой карты | софтфон звонит на SIP-адрес встречи | встреча создаётся через API как трансляция, пишется HLS |
| Что нужно | 360 Business и OAuth на Диск | только ссылка на встречу | платный аддон SIP | тариф с трансляциями |
| Задержка | до 24 ч | реальное время | реальное время | реальное время |
| Ресурсы на встречу | ~0 | ~0.5–1 ГБ RAM и заметный CPU | ~50 МБ | ~100 МБ |
| Ломается от | ничего | редизайна интерфейса Телемоста | почти ничего | ничего |
| Главный минус | кто-то должен нажать «Запись» | самый хрупкий и прожорливый | занимает лицензию коннектора | встреча становится публичной трансляцией |

**Что реализовано здесь — путь B.** Он работает на любой встрече, даже чужой,
и ничего не требует от организатора, кроме ссылки. Так же устроены рыночные
боты (Recall.ai, Fireflies и другие): для Google Meet и Телемоста нет bot API,
боты заходят через автоматизацию браузера. Цена — хрупкость: см. раздел
«Ограничения» в README.

## 4. Устройство

```
 Telegram: ссылка на встречу
        │
        ▼
 service/bot.py ── systemd-служба, long polling, только стандартная библиотека
        │  docker run (одноразовый контейнер на встречу, лимиты памяти и CPU)
        ▼
 poc/recorder/join_telemost.py ── Playwright + Chromium под Xvfb;
        │  PulseAudio (виртуальная карта) + ffmpeg → audio.wav 16 кГц моно
        ▼
 poc/pipeline/brief.py ── нарезка на куски, расшифровка с диаризацией
        │  (OpenAI), правка терминов, бриф строгим JSON, проверка цитат
        ▼
 Telegram: бриф + файл стенограммы   [+ WEBHOOKS: см. docs/webhook.md]
```

Почему так:

- **Long polling, а не вебхук Telegram** — не нужны ни домен, ни TLS, ни
  открытый порт.
- **Тяжёлое — в одноразовых контейнерах.** Сам бот занимает десятки мегабайт
  (в юните стоит `MemoryMax=200M`), а запись и расшифровка живут в контейнерах
  со своими лимитами: падение рекордера не роняет бота и соседей по серверу.
- **Только стандартная библиотека** в боте: на небольшом сервере лишние
  зависимости стоят дороже удобства.

## 5. Конвейер по шагам

1. **Запись.** Звук браузера идёт в виртуальную карту PulseAudio, ffmpeg пишет
   её в wav 16 кГц моно. Бот уходит сам, когда остался один дольше 90 секунд
   или по команде `/stop`.
2. **Нарезка.** Куски по 10 минут — чтобы каждый укладывался в жёсткий
   лимит эндпоинта расшифровки (25 МБ на файл). Кусок короче —
   дешевле повтор при сбое.
3. **Расшифровка.** `gpt-4o-transcribe-diarize` (`diarized_json`), куски
   считаются параллельно. Если в `voices/` лежат образцы голосов, они
   передаются как `known_speaker_references`, и вместо `A, B, C` в стенограмме
   сразу настоящие имена.
4. **Правка терминов.** Для стенограммы от локальной расшифровки (она пишет
   английские названия на слух) — механическая замена типичных искажений до
   того, как текст увидит модель брифа (`TERM_FIXES` в коде и `TERM_FIXES_EXTRA`
   в `.env`). Для пути через OpenAI этот шаг пропускается: подсказки терминов
   там задаются через `STT_VOCABULARY`.
5. **Бриф.** Модель собирает строгий JSON (`response_format: json_schema`).
6. **Проверка цитат.** Каждый пункт обязан нести дословную цитату и таймкод
   из стенограммы; пункт без подтверждения выбрасывается. Это дешёвая и жёсткая
   защита от выдумок.
7. **Доставка.** Бриф и стенограмма в чат; при настроенных `WEBHOOKS` — ещё и
   во внешние системы.

Пример входа и выхода — `docs/sample-transcript.txt` и `docs/sample-brief.json`
(выдуманные).

### Выбор расшифровки

| | OpenAI `gpt-4o-transcribe-diarize` | Yandex SpeechKit v3 | Своя видеокарта (GigaAM + pyannote) |
|---|---|---|---|
| Цена | ~$0.006/мин | по прайсу Яндекса | 0 |
| Диаризация | встроена | по каналам | делается сама |
| Данные | уходят в OpenAI | остаются в РФ | остаются у вас |

## 6. Ресурсы сервера

Замер на двух одновременных записях встречи вдвоём: в среднем 509 МиБ и
0.36 ядра на рекордер, пик 576 МиБ и 0.8 ядра (пик — старт браузера). На
большой встрече браузер декодирует больше потоков, поэтому на контейнер
стоят лимиты `--memory=2000m --cpus=1.5`. Отсюда рекомендация: на сервере
с 2 ядрами и 4 ГБ — `MAX_CONCURRENT=1` или `2` и небольшой swap как страховка
от всплесков. Час записи — около 115 МБ на диске: чистите старое командой
`/delete`; когда занято 85% диска, `/status` предупредит.

Сборка образа записи на двух ядрах заметно грузит сервер: если на нём живут
другие сайты, устанавливайте в тихое время.

## 7. Приватность и право

Это разговоры живых людей, поэтому:

- **Предупреждайте участников.** Бот заходит под видимым именем (`BOT_NAME`),
  но запись всё равно должна быть согласована с теми, кто на встрече.
  В ряде стран запись разговора без согласия участников незаконна.
- **Звук уходит в OpenAI**, то есть за пределы вашего контура. Если это
  неприемлемо — используйте локальную расшифровку (`local-stt.md`) или другого
  провайдера.
- **Доступ.** Бот отвечает только чатам из `ALLOWED_CHATS`; пустой список
  означает «никого», а не «всех» — бот умеет ходить на встречи и тратить
  деньги на расшифровку.
- **Хранение.** Аудио лежит в `jobs/` до удаления командой `/delete`;
  стенограммы и брифы — там же. `.env` и `profile/` хранят секреты и сессию
  Яндекса: права 600 и никуда не публиковать.

## 8. Риски

| Риск | Что делать |
|---|---|
| Телемост меняет вёрстку — бот перестаёт заходить | селекторы собраны в `join_telemost.py`; Телемост размечает интерфейс стабильными `data-testid`, а не классами — цепляться надо за них; см. `--discover` и `--selectors` |
| Телемост не пускает Chromium | подмена User-Agent; при неудаче — Google Chrome вместо Chromium |
| Комната ожидания не пропускает бота | бот ждёт впуска до 3 минут; организатор должен его принять или разрешить вход по ссылке без ожидания |
| Сервер не тянет параллельные встречи | `MAX_CONCURRENT`, лимиты контейнеров, swap; при росте — отдельный сервер |
| OpenAI снимает диаризацию | `stt-alternatives.md` |
| Персональные данные в OpenAI | локальная расшифровка или другой провайдер |
