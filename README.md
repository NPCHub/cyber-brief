# Cyber Brief

Телеграм-бот, который заходит на встречу в Яндекс Телемосте, записывает звук,
расшифровывает его с разделением по голосам и присылает в чат короткий бриф:
что решили, кто что должен сделать, какие идеи прозвучали и что осталось
нерешённым.

Вы пишете боту ссылку вида `https://telemost.yandex.ru/j/...` — через
некоторое время после конца встречи в тот же чат приходит бриф и файл со
стенограммой.

## Как выглядит результат

Вымышленная встреча на пять реплик — [`docs/sample-transcript.txt`](docs/sample-transcript.txt),
бриф по ней — [`docs/sample-brief.json`](docs/sample-brief.json). В Телеграме
он приходит примерно так:

```
📋 Встреча в Телемосте, 07.10 11:00

Договорились выкатить новую форму заявки в пятницу, при условии
проверки на телефонах до четверга.

🎙 Кто говорил
• Анна — метка A
• Борис — метка B

📌 Коротко
• Вёрстка формы готова, осталась проверка на телефонах.
• Релиз назначен на пятницу.

⚖️ Решения
• Выкатить новую форму заявки в пятницу [00:00:41]

✅ Задачи
• Проверить форму на телефонах и прислать отчёт
   Борис · срок: четверг вечером [00:00:41]

💡 Идеи
• Присылать уведомление в телеграм о каждой новой заявке — Виктор

❓ Открытые вопросы
• Кто пишет текст письма клиенту?
```

У каждого пункта есть дословная цитата и таймкод из стенограммы (в JSON; в
сообщении остаётся таймкод); пункт без подтверждения бот выбрасывает. Имена вместо «спикер A» бот берёт из самих
реплик («Борис, а ты…») и, если вы положили образцы голосов, из узнавания по голосу.

## Что нужно до начала

1. **Сервер на Linux** (проверялось на Debian/Ubuntu) с доступом по SSH и
   правами root или sudo. Минимум — 2 ядра и 4 ГБ памяти, 10 ГБ свободного
   диска (образ записи занимает около 2 ГБ, час записи — ещё ~115 МБ).
   Сервер должен достукиваться до `api.telegram.org` и `api.openai.com`.
2. **Телеграм-бот.** Создайте его у [@BotFather](https://t.me/BotFather)
   командой `/newbot` и сохраните токен. Если хотите звать бота в групповой
   чат — там же отключите ему privacy mode (`/setprivacy` → Disable).
3. **Ключ OpenAI** с положительным балансом: [platform.openai.com/api-keys](https://platform.openai.com/api-keys).

## Установка

```bash
git clone https://github.com/<org>/ai-brief && cd ai-brief
./install.sh
```

Установщик проверяет, что на сервере есть docker, Python 3.11+, ffmpeg и curl
(чего нет — ставит из apt или говорит, что поставить руками), спрашивает токен
бота, ключ OpenAI, чат и часовой пояс, собирает образ записи (первый раз
5–15 минут), заводит службу `ai-brief-bot` с автозапуском и в конце проверяет,
что служба жива и бот отвечает.

Токен и ключ проверяются прямо при вводе. Если не знаете `chat_id` — оставьте
поле пустым: установщик попросит написать боту сообщение и найдёт чат сам.
Установщик можно запускать повторно: уже введённые значения он не трогает, а
работающую службу не перезапускает (вдруг идёт запись).

Что делать дальше:

1. Откройте своего бота в Телеграме и отправьте `/start`.
2. Пришлите ссылку на встречу. Бот зайдёт на неё как участник «Cyber Brief»
   (имя меняется настройкой `BOT_NAME`), а после встречи пришлёт бриф.
3. Если бот отвечает «чат не в списке разрешённых» — впишите показанный им
   `chat_id` в `.env` (`ALLOWED_CHATS=`) и выполните `systemctl restart ai-brief-bot`.

Проверить без встречи: `/status` в боте покажет, жива ли служба, есть ли образ
записи, что с памятью и диском.

### Настройки

Все — в файле `.env` в каталоге репозитория. Полный список с пояснениями —
[`.env.example`](.env.example). Обязательны три: `TELEGRAM_BOT_TOKEN`,
`OPENAI_API_KEY`, `ALLOWED_CHATS`. Остальное — по желанию: `OWNER_IDS`,
`TZ`, `BOT_NAME`, `MAX_CONCURRENT`, `LLM_MODEL`, `STT_VOCABULARY`,
`WEBHOOKS`. После правки `.env`:
`systemctl restart ai-brief-bot` (не во время записи).

### Обновление, удаление

```bash
git pull && ./install.sh           # образ пересоберётся, служба останется как есть
systemctl restart ai-brief-bot     # когда нет записи — применить обновление
./install.sh --uninstall           # остановить службу, снять автозапуск
```

`--uninstall` оставляет на месте записи (`jobs/`), настройки (`.env`), голоса
и сессию Яндекса. Чтобы сменить токен бота, не светя его в переписке:
`sudo ./service/set-token.sh`.

Лог службы — `/var/log/ai-brief-bot.log`.

## Команды бота

| Команда | Что делает |
|---|---|
| `/brief <ссылка> [минут]` | прийти на встречу (или просто пришлите ссылку; в группе — тегните бота) |
| `/stop` | закончить запись раньше |
| `/status` | жива ли служба, что записывается, состояние сервера |
| `/history` | прошлые встречи: бриф и стенограмма по кнопке |
| `/delete` | освободить диск: удалить аудио или стенограмму с брифом |
| `/voices` | образцы голосов для узнавания людей по имени |
| `/login` | войти в Яндекс по QR, чтобы бот заходил под аккаунтом, а не гостем |
| `/link`, `/unlink` | привязать или отвязать чат (для владельца) |
| `/chats` | какие чаты обслуживаются |
| `/push` | дослать готовые брифы на адреса из `WEBHOOKS` |
| `/restart` | перезапустить службу — на крайний случай |
| `/help` | справка |

## Сколько это стоит

Деньги уходят только на OpenAI. Расшифровка `gpt-4o-transcribe-diarize` —
около **$0.006 за минуту звука, то есть ~$0.36 за час встречи**; бриф собирает
модель `gpt-5-mini` и стоит ещё несколько центов. Двухчасовая встреча на
21 человека обошлась в $0.82. Сервер — ваш собственный; на самом дешёвом
хватает для одной встречи за раз.

## Ограничения

Назовём их честно.

- **Бот заходит на встречу как обычный участник через браузер, поэтому
  ломается при обновлениях интерфейса Телемоста.** Так уже было 22 сентября
  2026. Чинится правкой селекторов в `poc/recorder/join_telemost.py`
  (режим `--discover` сохраняет скриншот и HTML страницы входа, по ним
  видно, что поменялось).
- **API Телемоста подключения к встрече не даёт**, другого пути нет:
  у его API нет ни записи, ни ботов (подробности — `docs/TZ.md`).
- **OpenAI снимает модель с диаризацией 26 февраля 2027.** После этой даты
  бесплатной замены с разделением по голосам у них не остаётся: бриф будет
  работать, но без разделения по спикерам. Варианты — в `docs/stt-alternatives.md`.
- **Расшифровка отправляет звук встречи в OpenAI**, то есть за пределы вашего
  контура. Кому это не подходит — путь через свою видеокарту описан
  (`docs/local-stt.md`), но требует отдельного сервиса, который в этот
  репозиторий не входит.
- **Согласие участников.** Запись разговора надо согласовывать с теми, кто на
  нём присутствует; бот виден в списке участников под своим именем, но это не
  заменяет предупреждения.
- Если на встрече включена комната ожидания, организатор должен впустить бота:
  он ждёт до 3 минут и уходит, если его не впустили.
- Рассчитано на Телемост и русскую речь; одна встреча — один браузер, поэтому
  число одновременных записей ограничено `MAX_CONCURRENT` и вашим сервером.

## Устройство

Коротко: `service/bot.py` — служба на long polling без зависимостей; каждая
встреча — одноразовый docker-контейнер из `poc/recorder/` (Chromium + Xvfb +
PulseAudio + ffmpeg), расшифровку и бриф делает `poc/pipeline/brief.py`.
Подробнее — [`docs/TZ.md`](docs/TZ.md). Доставка брифов во внешние системы —
[`docs/webhook.md`](docs/webhook.md). Папка `local/_archive/` — архив первой
схемы локальной расшифровки, на работу бота не влияет.

## Если что-то не работает

| Что видите | Что делать |
|---|---|
| Служба не стартует, в логе «TELEGRAM_BOT_TOKEN не задан» | вписать токен в `.env` или `sudo ./service/set-token.sh` |
| В логе «Telegram отклонил токен (401)» | токен неверный или отозван: `sudo ./service/set-token.sh` |
| «нет связи с api.telegram.org» | сервер не достаёт Telegram: проверьте сеть и блокировки |
| Бот пишет «Нет образа записи» | `./install.sh` или `docker build -t ai-brief-recorder:poc poc/recorder` |
| Бот пишет «Не задан OPENAI_API_KEY» | вписать ключ в `.env`, `systemctl restart ai-brief-bot` |
| «Не получилось записать встречу» | смотрите `jobs/<встреча>/recorder.log`: чаще всего поменялся интерфейс Телемоста или ссылка недействительна |
